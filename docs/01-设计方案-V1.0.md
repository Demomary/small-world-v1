# 《小小世界》V1.0 设计方案整理

## 0. 产品一句话

**面向 3～7 岁儿童的互动探索型游戏世界。**

它不是传统课程 App，也不是把知识点做成题库；核心是一个会持续变化、会记住孩子行为的数字世界。

核心循环：

```text
观察 / 发现
    ↓
好奇 / 提问
    ↓
探索 / 行动
    ↓
结果
    ↓
理解
    ↓
新的问题 / 新的探索
```

---

## 1. 年龄与成长

年龄范围：3～7 岁。

四个阶段：

- 3～4：看、听、摸、动、模仿
- 4～5：观察、比较、问“为什么”
- 5～6：为什么 + 怎么办，开始实验与计划
- 6～7：条件、因果、设计、工程、创造

年龄用于安全和适龄边界，不作为唯一难度控制变量。难度还由掌握程度、能力、兴趣、行为和上下文共同决定。

同一个知识节点允许反复出现，但深度随儿童状态变化。

## 2. 儿童账号与成长档案

家庭账户可包含多个儿童档案。

儿童档案包括：

- 姓名 / 昵称
- 生日 / 年龄
- 头像 / 外观
- 兴趣画像
- 知识掌握状态
- 能力画像
- 成就
- 收藏 / 发现目录
- 创造物
- 问题历史
- 世界状态

第一版以本地数据为主，不要求真实身份登录。

儿童切换自由；家长设置需要验证。

成长档案不是传统成绩单，主要用于驱动世界和推荐。

## 5. 核心游戏机制

可复用机制：

- 观察
- 搜索 / 找到
- 点击 / 长按 / 拖拽
- 移动
- 分类 / 匹配
- 记忆
- 实验
- 拼图
- 模仿
- 创造
- 角色扮演
- 身体运动

原则：**机制先于内容。**

例如：同一个“分类机制”可以用于动物、水果、交通工具、乐器等不同知识。

---

## 6. 大内容模块

音乐、古诗、体育、舞蹈、美术不是孤立课程，而是世界中的大区域。

标准链路：

```text
体验 → 互动 → 游戏 → 创造 → 知识连接
```

古诗词采用沉浸式场景，例如《静夜思》不是单纯显示文字，而是夜晚、月光、房间、庭院、声音、人物、时代背景共同组成体验。

体育覆盖足球、篮球、羽毛球、乒乓球、游泳、跑步、体操、武术、骑行、滑冰、排球、飞盘等；未来可加入动作识别。

音乐覆盖钢琴、吉他、小提琴、鼓、古筝等。

工程 / 机械 / 工业 / 机器人是重要特色方向，可形成“小小工程师世界”。

---

## 7. AI 定位

AI 是智能层，不是游戏引擎。

儿童可以自然语言与 NPC / 世界互动，但 LLM 不能直接修改世界。

固定链路：

```text
儿童输入
   ↓
上下文解析
   ↓
知识 / 世界 / 儿童状态
   ↓
AI Planner
   ↓
结构化 Action
   ↓
规则验证
   ↓
游戏引擎
```

AI 可做：

- 问题理解
- 知识解释
- 追问
- 个性化推荐
- 下一步探索建议
- NPC 对话变化
- 世界事件建议

AI 不可做：

- 任意 JS 执行
- 直接修改 WorldState
- 直接修改年龄或安全策略
- 修改家长设置
- 修改儿童掌握度
- 绕过权限 / 规则

V1 使用 MockAI / 抽象 AI 接口，不依赖在线大模型。

---

## 8. 动态难度与推荐

儿童状态拆成：

- 兴趣
- 知识
- 能力
- 行为

难度是多维的，例如：

- 对象数量
- 分类数量
- 相似度
- 记忆负荷
- 提示程度
- 时间限制
- 操作复杂度

初始推荐模型：

```text
contentScore =
    interest      × 0.30
  + knowledgeGap × 0.25
  + abilityFit   × 0.25
  + novelty      × 0.10
  + worldContext × 0.10
```

推荐的对象应该是世界中的探索机会，而不只是“下一道题”。

## 9. 自然语言 / 语音

统一链路：

```text

    ↓

    ↓
Intent
    ↓
Context Resolver
    ↓
Knowledge / Child / World
    ↓
AI
    ↓
Structured Action
    ↓

    ↓

```

上下文至少包括：

- 当前场景
- 当前焦点对象
- 最近世界事件
- 最近问题
- 儿童状态
- 知识图

V1 先文字，不依赖 ASR。

## 10. 内容生产系统

新增内容不能要求程序员每次写新的运行时代码。

内容包应包含：

- 知识节点
- 适龄范围
- 深度 / 难度
- 场景位置
- 互动对象
- 对话
- 音效 / 动画
- 游戏 / 实验模板及参数
- 触发条件
- 事件
- 掌握规则
- 安全 / 家长说明
- 关联知识
- 本地化信息

流程：

```text
作者 / AI 辅助
    ↓
Draft
    ↓
Schema Validation
    ↓
Content QA
    ↓
安全 / 事实审核
    ↓
Preview
    ↓
Publish
```

LLM 可以辅助写内容，但不能绕过人工审核直接发布。

## 13. World Event

WorldEvent 与 ChildEvent 分离。

世界是事件驱动的，而不是每个物体每秒都做高成本模拟。

事件模型：

```typescript
interface WorldEvent {
  id: string;
  type: string;
  timestamp: number;
  source: string;
  sceneId?: string;
  targetId?: string;
  payload?: Record<string, unknown>;
  persistent: boolean;
}
```

事件可以由：

- 时间
- 天气
- 环境
- NPC / 动物
- 植物
- 儿童
- 知识
- 游戏 / 实验
- AI 推荐

触发。

第一版不实现复杂生态系统。

## 14. 输入系统

设备与游戏逻辑必须解耦。

未来输入源：

- 鼠标
- 触摸
- 键盘
- 手柄
- 语音
- 摄像头

统一为输入事件，再解析成语义 Action。

目标链路：

```text
Input
 ↓
HitTest / Context
 ↓
Interaction
 ↓
Action
 ↓
Validator
 ↓
Domain Handler
```

---

## 15. 持久化

世界必须持续存在。

状态分四类：

- Child State
- World State
- Progress State
- Event History

V1 目标使用 IndexedDB，并允许本地导出 / 恢复。

保存采用“快照 + 最近事件”的思路。

时间流逝使用 `lastActiveTime` 计算离线变化，不使用无限运行的持久 `setInterval`。

---

## 16. 隐私与儿童安全

数据分层：

- Level 0：临时、不保存
- Level 1：世界运行状态
- Level 2：儿童成长状态
- Level 3：敏感数据

Level 3 默认不保存。

V1 不要求实名。

AI 只接收最小必要上下文。

原始语音默认不保存；未来摄像头尽量本地处理、不默认上传原始视频。

删除儿童时应能删除对应世界、进度、问题、发现、创造和事件。

## 19. 游戏与实验

游戏与实验分开。

### 游戏

强调操作与体验，可有结果，但不以儿童分数为核心。

V1 已规划：

- 听声找动物
- 植物照护
- 简单观察 / 搜索

### 实验

循环：

```text
问题
 ↓
改变条件
 ↓
操作
 ↓
观察
 ↓
比较
 ↓
理解
 ↓
新问题
```

V1：冰融化实验。

## 20. NPC / 动物

NPC / 动物是 WorldObject，但行为使用确定性状态机，不使用 LLM Agent。

候选行为：

- idle
- wandering
- moving
- eating
- drinking
- sleeping
- fleeing
- following
- interacting

第一版不做复杂群体生态、繁殖、领地或社会层级。

---

## 21. Exploration Opportunity

不采用传统强制任务清单。

探索机会由世界事件、知识、动物、植物、天气、儿童行为等产生。

状态设计：

```text
available
noticed
active
completed
expired
ignored
```

忽略不是失败。

推荐应允许“横向发现”和“意外发现”，避免把孩子锁死在单一兴趣里。

---

## 22. Feedback / Audio / Animation

表现层只消费事件，不修改世界状态。

```text
WorldEvent
 ↓
FeedbackSystem
 ├── Animation
 ├── Audio
 ├── Camera
 ├── Character
 ├── Visual
 └── UI
```

反馈分：

- Ambient
- Discovery
- Major Discovery

避免大量闪烁、连续奖励音、强刺激。

## 23. 测试 / QA

四层：

1. 代码正确性
2. 世界逻辑正确性
3. 内容正确性
4. 儿童体验正确性

必须覆盖：

- Action
- Validator
- 世界因果链
- 存档 / 读档
- 时间推进
- 内容引用
- AI 结构化输出
- 权限边界
- 世界不变量

产品级验收：

- 不需要教程也能探索
- 能发现多个对象
- 能自然产生问题
- 操作会改变世界
- 第二次进入能看到后果
- 同一知识点能连接世界、问题、游戏、实验

## 25. V1 最终产品心脏

```text
WORLD
  ↓ Event
Exploration
  ↓ Child
Action
  ↓ WorldState
  ↓ Event
Knowledge / Game / Experiment
  ↓ Child Signal
  ↓ Recommendation
  ↓ WORLD
```

核心原则只有三条：

1. **WorldState 是世界唯一事实来源。**
2. **改变世界必须表现为 Action。**
3. **发生过的事情表现为 Event。**

AI、知识、动画、UI 都围绕这三条工作，而不能反过来破坏它们。
