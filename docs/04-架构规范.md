# 架构规范与不变量

## 1. 唯一事实来源

`WorldState` 是世界当前状态的唯一事实来源。

Pixi、UI、AI、动画、音频都不能自己保存一份“真正的世界状态”。

## 2. Action / Event 区别

### Action

表示“准备做什么 / 正在做什么”。

例：

```text
MOVE
PICK
WATER
PLANT
TRAVEL
```

### Event

表示“已经发生了什么”。

例：

```text
object.picked
plant.watered
plant.grew
scene.entered
```

## 3. 状态改变原则

任何持久世界变化都必须能追溯到 Action 或明确的 World System 模拟。

不允许：

```ts
button.onclick = () => world.objects.xxx.state.foo = 1;
```

应当：

```text
button
 ↓
Action
 ↓
Validator
 ↓
Handler
 ↓
WorldState
 ↓
Event
```

## 4. Renderer 规则

Renderer 只负责把 WorldState 投影成视觉表现。

原则：

```text
WorldObject
   ↕ projection
WorldView / Pixi
```

不要把 `Sprite / Container / Graphics` 直接保存到 WorldObject。

## 5. 输入规则

输入设备与游戏语义解耦。

```text
pointer / touch / keyboard / voice / camera
                  ↓
             InputEvent
                  ↓
             Interaction
                  ↓
                Action
```

## 6. AI 权限边界

AI 输出只能是白名单结构化动作。

例如：

```json
{
  "type": "SHOW",
  "targetId": "butterfly_001"
}
```

不能输出：

```text
运行任意 JavaScript
修改 parent settings
修改 child age
修改 mastery
直接写 IndexedDB
```

## 7. Knowledge 不直接改世界

知识系统可以：

- 解释
- 建议
- 关联
- 产生问题 / 探索机会

但不能直接修改 WorldState。

## 8. Animation 不负责业务

动画播放完了不等于世界已经发生变化。

正确：

```text
WorldState 改变
 ↓
Event
 ↓
Animation
```

错误：

```text
Animation 播放完成
 ↓
直接修改世界
```

## 9. 生命周期与位置分离

对象生命周期：

```text
active
consumed
destroyed
```

对象位置：

```text
scene
carried
container
inventory
```

例如种子种下之后：

```text
seed.lifecycle = consumed
```

而不是直接删除对象。

## 10. 模拟与渲染频率分离

不要为了视觉刷新而把世界逻辑每帧永久写入存档。

例如植物成长应采用：

```text
elapsed time
 ↓
simulation
 ↓
state
```

而不是：

```text
setInterval
 ↓
每秒修改存档
```

## 11. 世界事件历史

事件历史用于：

- 调试
- AI 上下文
- 儿童成长分析
- 问题关联
- 世界因果追踪

可以做容量上限与聚合，但不能破坏当前状态的可恢复性。

## 12. 内容与运行时分离

未来应做到：

```text
JSON / Content Package
      ↓
ContentRepository
      ↓
Runtime Engine
```

而不是：

```text
App.ts
 里面硬编码全部内容
```

## 13. 世界不变量

后续测试至少保证：

### 对象唯一

同一个逻辑对象 ID 不重复。

### 携带唯一

一个角色当前只能有一个手持对象（V1）。

### 生命周期一致

`consumed / destroyed` 对象不可再次普通交互。

### 场景一致

对象必须位于合法位置。

### 花盆一致

`occupied=true` 时不能再次普通种植。

### 水壶一致

水量不能 < 0 或 > capacity。

### 植物一致

```text
growth ∈ [0,1]
water ∈ [0,1]
health ∈ [0,1]
sunlight ∈ [0,1]
```

### 世界时间一致

小时归一化到：

```text
0 <= hour < 24
```

## 14. 推荐的最终模块依赖方向

```text
UI
 ↓
App
 ↓
Domain Systems
 ↓
Infrastructure
```

更细：

```text
Input
 ↓
Interaction
 ↓
Action
 ↓
Validator
 ↓
Domain Handler
 ↓
WorldEngine / World Systems
 ↓
WorldState
 ↓
WorldEvent
 ↓
Feedback / Knowledge / Recommendation / Persistence
```

## 15. 禁止依赖

```text
UI            ✕ IndexedDB
UI            ✕ 直接写 WorldState
AI            ✕ WorldState
AI            ✕ PixiJS
Knowledge     ✕ PixiJS
Game          ✕ IndexedDB
Renderer      ✕ 业务逻辑
Animation     ✕ 业务逻辑状态修改
```

## 16. V1 的最小闭环

任何新增功能都要问：

```text
它是否能进入世界？
它是否能被观察？
它是否产生 Action？
它是否改变 WorldState？
它是否产生 Event？
它是否产生知识 / 游戏 / 实验 / 新探索？
退出后重新进入是否还能看到结果？
```

不能回答这些问题的内容，不应该优先于主闭环。
