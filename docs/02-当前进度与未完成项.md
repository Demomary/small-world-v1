## B. 设计已经确定，但源码还没有按最终架构完整实现

### 1. ActionValidator

设计要求：

```text
Input / AI / NPC
    ↓
Action
    ↓
ActionValidator
    ↓
Domain Handler
```

当前：`WorldEngine.dispatch()` 内部直接做大部分参数检查和状态变化。

**后续应优先拆出。**

### 2. ActionHandler / Domain Handler

设计要求：

- PlantActionHandler
- ObjectActionHandler
- MovementActionHandler
- GameActionHandler
- ExperimentActionHandler
- CreationActionHandler
- NPCActionHandler

当前：主要集中在 `WorldEngine.ts` 与 `App.ts`。

### 3. InputManager / InteractionSystem

前期设计已经确定统一输入抽象，但当前实际代码主要是：

```text
Pixi pointer
 ↓
Renderer 自定义 DOM Event
 ↓
App.onObject / onWorldPoint
 ↓
直接生成 Action
```

`src/input/` 和 `src/interaction/` 目前还是空目录。

**后续应逐步把 App 中的输入处理迁入独立模块。**

### 4. Focus System

设计要求：Focus 是动态上下文。

当前只有：

```ts
private focus?: string;
```

还没有正式的 FocusManager / FocusScore / FocusRadius。

### 5. Interaction Range

当前有固定的 110/115 像素距离判断，但没有正式的数据模型。

应区分：

- interaction radius
- focus radius
- click target

### 6. SceneManager

当前可以切换场景，但场景管理直接写在 `App.travel()`。

还没有独立 `SceneManager` 生命周期：

```text
enter → load → activate → running → deactivate → unload
```

### 7. Camera

现已新增 `src/render/Camera.ts`，实现统一世界坐标、屏幕坐标转换、角色跟随和镜头边界；手机可横向拖动浏览场景。

后续仍可补充用户控制缩放、平滑镜头和更复杂的场景边界。

### 8. Collision / Walkable

当前角色只是把坐标限制在矩形范围内，没有障碍物碰撞和路径规划。

### 9. 正式 ExplorationOpportunity State

当前 `Opportunity` 是一个计算出来的列表，没有独立的：

```text
available / noticed / active / completed / expired / ignored
```

### 10. 推荐系统

当前没有真正执行设计中的：

```text
interest × knowledgeGap × abilityFit × novelty × worldContext
```

目前只是根据当前场景给固定机会。

### 11. AI Runtime

当前 `MockAI.ts` 是一个简单字符串关键字匹配函数。

还没有：

```text
ContextResolver
IntentResolver
AIPlanner
Structured Action
ActionValidator
```

### 12. Knowledge Graph

当前是数组 + 关键字匹配。

还没有完整的：

- prerequisite
- related
- causes
- part_of
- contrasts_with
- example_of
- used_in
- question_about

### 13. Creation System

设计中存在完整的创造机制，但当前尚未实现真正的建造 / 绘画 / 音乐创作持久化实体。

### 14. Character System

当前角色状态混在普通 `WorldObject.state` 里。

还没有正式：

```text
Character
CharacterController
AnimationController
```

### 15. Asset System

当前没有真正的资源目录、资源 ID、授权元数据和版本系统。

### 16. Content Pipeline / Schema

当前内容直接在 `App.createWorld()` 中硬编码。

这是后续非常重要的拆分项：

```text
App.createWorld()
        ↓
ContentRepository / JSON
```

### 17. 完整测试体系

当前已有 9 项测试，覆盖种植、首次浇水与补水、镜头坐标和旧存档布局迁移；尚不是完整系统测试体系。

需要继续增加：

- Action tests
- Validator tests
- Plant tests
- Persistence tests
- Migration tests
- World invariant tests
- Exploration tests
- Knowledge tests
- AI safety/permission tests
- UI smoke tests

## C. 当前源码的已知限制

### 1. 本机依赖与运行已验证

依赖已安装，`npm run build` 和 `npm test` 均通过。已使用 Playwright 驱动本机 Edge 验证桌面与手机布局、种植、场景切换、补水、存档恢复和弹窗流程。实机截图位于 `artifacts/visual/`。

### 2. 当前 `App.ts` 仍然过重

约 500 行，承担了：

- 世界初始化
- 输入
- 移动
- 交互
- UI
- 场景
- 游戏入口
- 实验入口
- 存档
- 事件响应

后续应按照前面设计的模块边界逐步拆分。

### 3. 当前 IndexedDB 不是正式 Repository 层

目前 `Persistence` 同时处理 LocalStorage 和 IndexedDB。

后续应变成：

```text
Persistence API
   ├── SnapshotStore
   ├── EventStore
   └── IndexedDBAdapter
```

### 4. 当前植物模型仍然是 MVP 生物模型

只用于表达：

```text
水 / 阳光 / 健康
     ↓
生长
     ↓
阶段
```

不是完整植物生理模型。

### 5. 当前动物并不是真正的状态机

现在是轻量向量运动，不是完整的：

```text
idle → wander → eat → drink → rest → flee ...
```

这是后续需要补的一块。

## D. 推荐下一阶段本地开发顺序

不要先继续堆很多内容。建议严格按下面顺序：

```text
1. Input / Interaction 抽象
2. ActionValidator
3. Domain ActionHandler
4. Character / Focus / InteractionRange
5. SceneManager / Camera / Walkable
6. Persistence 拆层
7. Exploration 状态机 + 推荐
8. Knowledge Graph
9. Game / Experiment 统一生命周期
10. AI Context + Structured Action
11. Asset / Content JSON
12. 更多内容
13. 完整测试
14. 儿童体验打磨
```

这样不会把当前原型推倒重做。
